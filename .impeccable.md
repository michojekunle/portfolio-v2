## Design Context

### Users
Recruiters, potential clients/collaborators, and technical peers evaluating Michael Ojekunle (software engineer & builder) via his personal portfolio, blog, work case studies, and a directory of shipped tools. Visits range from a 30-second scan on mobile (a link shared on X/LinkedIn) to a slow, deliberate desktop read of the About/Work pages before a hiring or collaboration decision.

### Brand Personality
Precise, editorial, quietly confident. "Curiosity is the constant." Faith-driven and unhurried in tone — the copy explicitly favors restraint over hype ("less mythical, more shippable"). Engineer, writer, builder — craftsman-like, not salesy.

### Aesthetic Direction
Editorial/magazine minimalism. Default theme is **Noir** — true monochrome (black/white/gray, zero color accent) — chosen deliberately over the previous warm-ochre gold default. Other selectable themes (ochre, ink, forest, cobalt, rose) exist via a user-facing theme selector and must keep working. Display type is a large serif (Fraunces) with huge fluid `clamp()` headlines on marketing pages; UI/meta text is a tracked-out uppercase mono (JetBrains Mono) in small sizes (9-11px) for labels, eyebrows, and dashboard chrome. Generous whitespace, hairline `--rule` borders, restrained motion (fade/reveal on scroll, no bounce). Both light and dark variants exist per theme via CSS custom properties (`--bg`, `--ink`, `--rule`, `--v3-accent`, etc. in `app/globals.css`).

### Design Principles
1. **Respect the existing token system.** Every color/spacing decision should route through the established CSS variables (`--bg`, `--bg-2`, `--paper`, `--ink`, `--ink-2/3/4`, `--rule`, `--v3-accent`, `--maxw`, `--gutter`) — never hardcode new colors that bypass theming.
2. **Editorial hierarchy over generic dashboard patterns.** Marketing/content pages (home, about, work, blog) keep fluid serif display type and asymmetric layouts; admin/tool UIs (job tracker, journal, etc.) use the tighter fixed-scale shadcn-style system already in place there — don't blend the two.
3. **Mono meta stays small and tracked-out**, even on mobile — it's a deliberate voice (uppercase, wide letter-spacing, 9-11px), not a bug to "fix" by enlarging.
4. **Adapt, don't amputate.** On small screens, reflow multi-column grids to single column and stack hero meta rows — never hide content or drop functionality to make something fit.
5. **Follow the codebase's existing responsive convention**: Tailwind v4 arbitrary breakpoints already in heavy use (`max-180:`, `max-[920px]:`, `max-[720px]:`, `max-[480px]:`) — extend this pattern rather than introducing a new breakpoint system.
